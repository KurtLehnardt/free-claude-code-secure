# Egress allowlist for fcc-server's outbound LLM/provider traffic.
#
# SOURCE OF TRUTH: every active (uncommented) hostname below was extracted
# from the `default_base_url=...` constants actually assigned to each
# ProviderDescriptor in
#   src/free_claude_code/config/provider_catalog.py
# (verified by reading that file directly, NOT the credential_url /
# dashboard links it also carries -- those are where a human gets an API
# key, not hosts the running process ever calls). Two hosts below were
# found by tracing beyond provider_catalog.py into the modules that
# actually issue HTTP requests, because provider_catalog.py alone does not
# tell the whole story for every provider -- see the "found by call-site
# tracing" notes inline.
#
# Format: one hostname per line, Squid `dstdomain` syntax.
#   example.com   -> matches that exact host only
#   .example.com  -> matches that host AND any subdomain of it
# Lines starting with `#` and blank lines are ignored by Squid.
#
# This file is read by squid.conf via:
#   acl allowed_domains dstdomain "/etc/squid/allowed-domains.txt"
#
# Edit this file to add/remove providers, then
# `docker compose exec egress-proxy squid -k reconfigure` (or
# `docker compose restart egress-proxy`). No squid.conf change is needed
# for a plain hostname add/remove -- squid.conf only carries the two
# regex ACLs noted below for hosts whose region/project segment varies.

# Intentionally NOT listed above -- read before adding manually

# amazon Bedrock (bedrock-mantle.<region>.api.aws): NOT a plain dstdomain
# entry. BEDROCK_DEFAULT_BASE is "https://bedrock-mantle.us-east-1.api.aws/v1"
# and bedrock_base_url IS operator-overridable (region-scoped, per
# provider_catalog.py's own comment), so it's enforced via a dstdom_regex
# ACL in squid.conf that matches any region, not just us-east-1:
#   ^bedrock-mantle\.[a-z0-9-]+\.api\.aws$
# (An earlier draft of this file/squid.conf incorrectly targeted
# bedrock-runtime.*.amazonaws.com, which is AWS's native Bedrock Runtime
# API, not the Bedrock Mantle OpenAI-compatible endpoint this codebase
# actually calls. They are different hosts entirely.)
#
# Google Vertex regional host (<region>-aiplatform.googleapis.com): also
# enforced via dstdom_regex in squid.conf, not a plain-text line, because
# the region segment varies per operator (VERTEX_LOCATION setting):
#   ^[a-z0-9-]+-aiplatform\.googleapis\.com$
#
# api.anthropic.com / api.openai.com: deliberately left OUT of the active
# allowlist (not even as regex). Grepping the full source tree found no
# httpx/aiohttp/openai-SDK call anywhere that targets either host as an
# upstream URL:
#   - Anthropic wire format is INBOUND ONLY in this codebase -- fcc-server
#     receives requests in Anthropic's Messages API shape from local coding
#     agents and translates them to whichever OpenAI-compatible backend is
#     configured. There is no "Anthropic passthrough" provider in
#     PROVIDER_CATALOG, so the proxy itself never calls out to Anthropic.
#   - A plain api.openai.com/OPENAI_API_KEY integration is not a
#     configuration this app has; the "openai" provider_id's
#     default_base_url is chatgpt.com (see above), and api.openai.com only
#     appears as a JWT claim-namespace string, never a fetch target.
# If you extend this codebase with a direct Anthropic-passthrough or a
# plain api.openai.com/OPENAI_API_KEY integration, add the relevant host
# here at that time -- don't add it speculatively now.
#
# azure_openai: no default_base_url in the catalog at all (base_url_attr
# only) -- it is 100% operator-supplied via AZURE_OPENAI_BASE_URL. Add
# your specific Azure resource host (e.g. <resource>.openai.azure.com)
# here yourself if you enable this provider; there is no sane project-wide
# default to ship.
#
# lmstudio / llamacpp / ollama (local): default_base_url values are all
# http://localhost:*. These are excluded on purpose -- they're not
# internet egress targets, and this deployment's `internal: true` network
# also makes them unreachable from inside the fcc-server container
# regardless (see the DECISION/TRADE-OFF comment in docker-compose.yml).
#
# web_fetch / web_search model tools (lite.duckduckgo.com, and whatever
# arbitrary URL a client asks web_fetch to retrieve): NOT LLM provider
# traffic, deliberately not allowlisted here as a matter of scope. See the
# docker-compose.yml DECISION/TRADE-OFF comment for the full story on why
# these tools don't work under this topology at all today (it's not just
# an allowlist gap).
